# 5. book/[id]/review — 챕터 리뷰 (Flutter 앱 + NestJS)

## 1. 개요

`book/[id]/review`는 한 챕터의 모든 소질문 답변을 모아 AI가 자서전 원고로 종합한 결과를 확인하는 화면이다. 앱에서는 읽기·듣기·사진 결과 확인까지만 제공하고, 직접 문장 수정과 사진 수동 삽입은 웹에서 한다.

- Flutter의 현재 라우트에는 review가 없다. 다권 도입 뒤에도 정적 GetX 라우트 `AppRoutes.bookReview`를 유지하고 `Get.toNamed(..., arguments: {'bookId': bookId, 'chapterId': chapterId})`로 전달하는 방식을 기준으로 한다.
- 작성 화면의 챕터 완료 CTA `리뷰하러 가기`는 이 화면을, `홈으로 이동`은 `/book` 허브를 향한다. `bookId`와 `chapterId`는 서버에서 소유/참여 권한을 검증한다.
- 현재 NestJS는 완료 장의 윤문 문단을 `GET /v1/book/pages`로 조립할 뿐, 챕터 종합 원고·리뷰·사진·TTS 기능은 제공하지 않는다. AI도 고정 응답 스텁이다.
- 웹의 기존 노트북은 유효한 참고 구현이나, 현재 `/mypage/notebook`은 단일 사용자·대목차(`contentId`) 기반이다. 신규 앱/공유 API의 다권 `bookId`/`chapterId` 범위와 혼동하지 않는다.

## 2. 유저 플로우

1. 사용자는 한 챕터의 마지막 소질문을 답변 또는 건너뛰기로 끝낸 뒤 `리뷰하러 가기`를 누른다. 앱은 GetX route argument를 전달한다.
2. 앱은 인증·책 권한을 포함한 리뷰 세션을 요청한다. 서버는 해당 챕터의 모든 확정 답변을 읽고, 저장된 종합 원고가 없으면 AI 자서전 원고를 생성한다.
3. 로딩 완료 후 챕터 제목, 종합 원고, 사용 가능한 사진 결과를 보여 준다. 원고는 읽기 전용이며 “웹에서 수정할 수 있어요”를 항상 안내한다.
4. `읽어주기`는 원고를 문장 또는 안전한 길이의 연속 청크로 순차 요청·재생한다. 긴 원고를 한 요청에 보내지 않고, 중지·네트워크 실패·다시 듣기 상태를 처리한다.
5. 무료 사용자는 AI 사진 1장 생성 결과만 볼 수 있고, 유료 사용자는 서버가 허용한 최대 5장의 사진 결과를 본다. 앱에서 직접 업로드·삭제·위치 변경은 하지 않는다.
6. 저장하면 첫 챕터에는 정확히 “챕터1 저장 완료”, 이후에는 “현재 챕터 저장 완료”와 “나중에 수정 가능해요”를 표시한다. CTA는 다음 챕터가 있으면 `다음 챕터 넘어가기`, 없으면 `홈으로 이동`(`/book`)이다.

## 3. 핵심 기능

| 기능 | 설명 | 상태 |
|---|---|---|
| 챕터 답변 종합 | 모든 소질문 확정 답변을 자서전 형태의 단일 원고로 생성·저장 | 신규 |
| 종합 원고 읽기 | 앱에서 챕터 원고와 문단 사이 사진 결과를 읽기 전용으로 표시 | 신규 |
| 웹 수정 안내 | 직접 편집 대신 웹 수정 가능 안내와 웹 진입 정책 제공 | 신규 |
| Naver Voice TTS | 서버가 Naver Voice(Clova 계열)로 합성하고 앱은 오디오만 재생 | 신규 전환 |
| 긴 원고 TTS 청킹 | 제공자 한도보다 작은 문장/문단 청크, 순차 재생·중지·재시도 | 신규 |
| 사진 결과 조회 | 무료는 AI 사진 1장, 유료는 허용된 사진 결과를 읽기 전용 표시 | 신규 |
| 수동 사진 삽입 | 앱에서는 제공하지 않음. 유료 웹 기능 | 앱 비범위 |
| 직접 문장 수정 | 앱에서는 제공하지 않음 | 앱 비범위 |
| AI와 함께 수정 | 중지 문장과 앞·뒤 문장(총 3문장)을 보이스 지시로 변경 | TODO/검토 |
| AI 사진 1장 만들기 | 사진이 없을 때 챕터 본문으로 생성해 첫 이미지 슬롯에 우선 배치 | TODO이지만 출시 전 개발·테스트 필수 |
| 무료/유료 접근 제어 | UI 숨김뿐 아니라 서버에서 사진 수·AI 수정 권한 검증 | 신규 |

### 플랜 규칙

- 무료: 수동 사진 넣기 불가, AI 사진 1장 만들기는 가능, AI 수정은 잠금이다.
- 유료: 챕터당 사진 최대 5장, AI 수정 이용 가능이다. 구체적인 티어 명칭이나 `T1 이상`은 아직 확정하지 않는다.
- 한도·권한·생성 횟수는 NestJS 서비스에서 검증한다. 앱의 버튼 숨김은 보조 UX일 뿐 권한 통제가 아니다.

## 4. 화면 구성

### 원고·음성

- 헤더에 장 번호·제목과 진행 상태를 표시한다. 본문은 큰 읽기용 글자, 문단 간 여백, 문단 사이 이미지로 구성한다.
- `읽어주기`/`중지`는 명확한 단일 제어로 제공한다. 앱은 현재 재생 문장을 강조할 수 있으나, 제공자의 단어 시간 정보 유무와 실기기 검증 후 범위를 확정한다.
- 재생 실패 시 현재 문장부터 재시도하거나 처음부터 다시 듣기를 제안하며, 제공자 키·음성 설정값은 노출하지 않는다.

### 사진·수정 안내·완료

- 사진은 서버가 내려준 placement 순서대로 문단 사이에 표시한다. 앱은 결과를 보기만 하며 파일 선택·업로드·삭제·위치 변경 컨트롤을 제공하지 않는다.
- 직접 수정 버튼 대신 “웹에서 수정할 수 있어요” 안내와 웹 URL/공유 정책을 제공한다. 로그인 세션을 어떤 방식으로 웹과 연결할지는 별도 결정이다.
- 저장 완료 패널은 “나중에 수정 가능해요”를 공통으로 보인다. 문구의 `챕터1`은 첫 챕터에만 고정하고 나머지는 현재 챕터 번호 또는 “현재 챕터”로 일반화한다.

## 5. API 엔드포인트 (NestJS)

### 현재 API

| Method | Path | 설명 | 상태 |
|---|---|---|---|
| `GET` | `/v1/chapters` | 단일 책 전제 장 목록·상태 | 기존 |
| `GET` | `/v1/book` | 단일 책 요약, 사진 수는 현재 항상 0 | 기존 |
| `GET` | `/v1/book/pages` | 완료 장의 `polished_text`를 페이지·문단으로 조립 | 기존 |
| `POST` | `/v1/questions/:id/followup/:fid/answer` | 꼬리답변·윤문 확정과 챕터 완료 여부 반환 | 기존 |

### 신규/제안 API

| Method | Path | 설명 | 상태 |
|---|---|---|---|
| `GET` | `/v1/books/:bookId/chapters/:chapterId/review` | 권한 검증, 챕터 원고·placements·플랜·저장 상태 조회 | 신규 제안 |
| `POST` | `/v1/books/:bookId/chapters/:chapterId/review/synthesize` | 모든 소질문 답변으로 종합 원고 생성/재생성 | 신규 제안 |
| `PATCH` | `/v1/books/:bookId/chapters/:chapterId/review` | 앱의 검토 완료·저장 상태 기록. 앱 본문 직접 편집은 허용하지 않음 | 신규 제안 |
| `POST` | `/v1/books/:bookId/chapters/:chapterId/review/tts` | 문장/청크 단위 Naver Voice 오디오 반환 | 신규 제안 |
| `POST` | `/v1/books/:bookId/chapters/:chapterId/review/images/generate` | AI 사진 1장 생성, 첫 placement 우선 배치 | 신규 제안·must 개발/테스트 |
| `POST` | `/v1/books/:bookId/chapters/:chapterId/review/voice-rewrite` | 중지 문장±인접 2문장과 음성 지시로 수정안 생성 | TODO/검토 |

Naver Voice 자격 증명과 이미지 제공자 키는 NestJS 환경변수/시크릿 저장소에만 보관한다. Flutter는 인증 토큰으로만 서버를 호출하며 제공자 API를 직접 호출하지 않는다.

## 6. 데이터 모델

| 모델 | 역할 | 변경 방향 |
|---|---|---|
| `book` | 현재 사용자당 1행인 책 요약 | 다권 `book_id`와 소유/참여 관계 기준으로 확장 |
| `user_chapter` / `user_question` | 사용자별 챕터·질문과 완료 상태 | `book_id` 범위와 review 가능 상태 추가 |
| `answer` / `answer_followup` | 원문·윤문 결과·꼬리답변 | 종합 입력 원천으로 사용 |
| 챕터 원고 | 현재 NestJS에는 없음 | `chapter_review` 또는 `chapter_notebook` 성격의 원고·AI 초안·상태 모델 신규 |
| 원고 block/placement | 현재 없음 | 단순 URL 배열 대신 `paragraphIndex` 또는 안정적 `anchor`와 media ID를 저장 |
| chapter media | 현재 사진 기능 없음 | 사용자 업로드/AI 생성 출처, MIME, 저장 위치, 생성 상태, 플랜 집계를 신규 |
| plan/entitlement | 현재 `user_setting`은 일일 알림만 보유 | 무료/유료 권한과 챕터별 수동 사진 최대 5장·AI 수정 잠금의 서버 판정 모델 신규 |

문단 사이 이미지는 URL 배열만으로 위치를 보존할 수 없다. 원고 수정 시 이동 규칙을 정할 수 있도록 block ID 또는 문단 인덱스와 anchor(앞 문장 식별자)를 함께 두는 모델을 후보로 한다. AI 사진은 첫 이미지 슬롯을 우선 사용하되, 기존 첫 슬롯 사진을 덮어쓸지·다음 빈 슬롯으로 보낼지는 서버 정책으로 확정한다.

## 7. 기존 코드 참고

아래 경로의 존재와 동작을 확인했다.

| 영역 | 경로 | 참고 내용 |
|---|---|---|
| Flutter 책 허브 | `lib/feature/book/book_controller.dart`, `book_view.dart` | 단일 `/book`, 완료 장은 preview로 이동; review 경로 없음 |
| Flutter 라우팅 | `lib/core/route/app_routes.dart`, `app_pages.dart` | 정적 GetX 라우트 테이블, `bookId` argument 미도입 |
| Flutter 음성 UI | `lib/common/widgets/ds/app_voice.dart` | 녹음용 `AppMicButton`; TTS 플레이어/리뷰 음성은 없음 |
| NestJS 책 API | `server/src/book/book.controller.ts`, `services/book.service.ts` | `/v1/book`, `/v1/book/pages`; done 장 윤문 문단을 3문단 단위로 조립 |
| NestJS 답변·장 | `server/src/answers/`, `server/src/chapters/` | 1회 꼬리질문·윤문·챕터 완료 전환 |
| NestJS AI | `server/src/ai/services/ai.service.ts` | 꼬리질문·윤문만 있으며 현재 제공자 스텁 |
| NestJS 책 모델 | `server/src/book/entities/book.entity.ts` | 사용자당 1책, `photoCount`는 v1에서 항상 0 |

`server/src`의 `book`, `answers`, `chapters`, `ai`를 확인했으며 review/notebook/photo/TTS 전용 모듈은 확인되지 않았다.

## 8. 신규 개발 범위 요약

- Flutter: `bookId`/`chapterId` GetX argument 기반 review 라우트, 읽기 전용 원고·사진·TTS 상태, 웹 수정 안내, 저장 완료와 다음/홈 CTA.
- NestJS: 다권 권한, 챕터 종합 원고 생성·저장, 문단 placement와 미디어 모델, 플랜 entitlement·5장 한도 검증, Naver Voice 청크 프록시.
- NestJS: AI 사진 생성은 TODO이되 출시 전 개발·테스트가 필요한 백로그로 구현한다. 생성 실패·재시도·첫 슬롯 배치·민감정보 동의까지 시험한다.
- 공통: 웹 편집 결과가 앱 읽기 화면에 즉시 반영되는 버전·충돌 정책을 정한다. 앱은 직접 편집하지 않으므로 웹 저장본을 우선한다.

## 9. 열린 이슈 / 가정

1. 사용자가 요구한 “챕터1 저장 완료”는 1장에만 정확히 적용하고 이후 장에는 “현재 챕터 저장 완료”로 일반화했다. 모든 장에서 정확히 같은 문구가 필요하다면 제품 결정을 다시 받아야 한다.
2. Flutter와 Next.js는 현재 별도 사용자·DB·단일 책 모델이다. 실제 웹 수정 연결 전 `bookId` 매핑, 계정 공유, 권한과 웹 우선 충돌 처리를 확정해야 한다.
3. Naver Voice의 실제 TTS 한도, 청크 경계, 합성 지연, 재생 URL/스트리밍 방식, 문장 타이밍 메타데이터와 비용은 제공자 검증·실기기 테스트가 필요하다.
4. `AI와 함께 수정하기`는 확정 기능이 아니다. 중지→음성 입력→중지 문장과 앞·뒤 3문장 컨텍스트→수정안 즉시 반영의 UX·사실 보존·되돌리기·유료 권한을 검토한다.
5. AI 사진 1장 만들기는 TODO이지만 개발·테스트가 반드시 필요한 출시 전 백로그다. 이미지 생성 실패·재시도·부적절 결과 검수·첫 슬롯 우선 규칙을 검증해야 한다.
6. AI 이미지 생성 전, 사용자 답변의 민감정보를 외부 이미지 제공자에 전달한다는 고지·명시적 동의와 제공자의 학습 이용·보관·삭제 정책을 확인해야 한다.
7. 유료 플랜의 구체 티어, AI 사진 생성 횟수/비용 한도, 기존 사진이 5장일 때 AI 사진의 처리 정책은 미정이다.
