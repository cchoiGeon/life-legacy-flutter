# 01. 메인(랜딩) — 웹 (Next.js) 마케팅 랜딩페이지

## 1. 개요

- **목적**: 기존 `app/app/page.tsx`(01-현재-기능정의.md의 MKT-01, 현재 구현됨)를 아래 8개 섹션 순서로 재구성하는 광고·소개 중심 마케팅 랜딩페이지 개발가이드.
- **비범위**: Flutter 앱의 "index" 화면(→ [`01-landing.md`](./01-landing.md)), 로그인/회원가입 폼 자체(→ 02-login-signup, 작성 예정), FAQ 상세 화면 자체(→ 08-faq, 작성 예정. 이 문서는 랜딩에서 FAQ로 넘어가는 진입점만 다룬다).
- **대상 사용자**: 신규 방문자(비로그인 포함), 자서전을 부모님께 선물하려는 2030 자녀 세대, 직접 웹에서 작성·리뷰까지 하려는 시니어 사용자.
- **참고**: 이 화면은 **웹 전용**이므로, [00-index](./00-index.md)의 공통 구조 중 "API 엔드포인트 (NestJS)" 섹션은 이 문서에서 **Next.js Route Handler**(`app/app/api/*`)로 대체해서 다룬다 — 이 랜딩·후기·가격 기능은 NestJS(Flutter 전용 백엔드)가 아니라 기존 Next.js API와 같은 스택으로 구현하는 것이 자연스럽다(§9-2 참고).
- **관련 문서**: [00-index](./00-index.md), 01-현재-기능정의(MKT-01, MKT-03, AUTH-01b), 02-웹앱-분리-로드맵(§3.4 결제·§4 가족 패키지·§5 로드맵).

## 2. 유저 플로우

```
방문
  → ① 초반 후킹멘트("호사유피 인사유명" + 시작하기)
  → ② 기능 소개 스크롤
  → ③ 실제 후기 확인
  → ④ 개인정보보호 후킹 문구 확인
  → ⑤ 가격(무료 ~ T4) 비교
  → ⑥ 간단 FAQ 확인 → (더 필요하면) "FAQ 전체 보기" 버튼 → /faq
  → ⑦ 마무리 문구 + 후킹 글
  → ⑧ SNS 링크
  → 푸터(카피라이트·문의·소개 내비게이션)
```

어느 지점의 CTA("시작하기" 계열)를 눌러도 기존과 동일하게 `/intro`로 이동한다. `/intro`는 `(dashboard)` 라우트 그룹이라 미로그인 시 기존 대시보드 가드(AUTH-02, `(dashboard)/layout.tsx`)가 `/login`으로 리다이렉트한다 — **이 동작은 기존 그대로 유지**하며 이번 재구성 대상이 아니다.

## 4. 화면 구성

섹션은 사용자가 지시한 순서를 그대로 따른다. 각 섹션 옆에 기존 코드 대응 여부를 표기한다.

### ① 초반 후킹멘트
"호사유피 인사유명(虎死留皮 人死留名, 호랑이는 죽어서 가죽을 남기고 사람은 죽어서 이름을 남긴다)" 한자와 뜻 소개 + "시작하기" 버튼.
- 기존 히어로 섹션(`app/app/page.tsx` 182~253행)의 레이아웃(그라데이션 배경, 좌측 카피 + 우측 책 카드 비주얼)을 재사용하고 카피만 이 후킹멘트로 교체하는 것을 권장.

### ② 기능 소개 → ③ 실제 후기
- 기능 소개: 기존 `features` 배열(6개 카드, `app/app/page.tsx` 18~49행) 그대로 재사용 가능.
- 후기: **일단 목업 데이터로 시작**하고, 이후 실제 후기로 교체 가능해야 한다. 유저별 후기 DB·CRUD가 필요하며, 후기 레코드는 유저를 FK로 두되 **FK는 필수가 아니다**(이름만 입력한 방문자 후기도 등록 가능). 자세한 스키마·API는 §5, §6 참고.

### ③-1 개인정보보호 후킹 문구
사용자가 제시한 원문을 **현재 구현 상태에 맞게 각색**한 문구(안):

> 가족과 옛 이야기를 나누듯 편안하게 대화해 주세요. 안전 원칙을 바탕으로 소중한 이야기를 지켜드립니다.
>
> **데이터 보안 원칙**
> - **로그인 보호**: 비밀번호는 암호화(해시)하여 저장하고, 본인 세션에서만 내 기록에 접근할 수 있습니다. *(SNS 간편 로그인은 도입 예정입니다 — §9-1)*
> - **목적 외 사용 제한**: 입력하신 내용은 자서전 작성·다듬기 목적 외에는 사용하지 않으며, AI 제공사와의 계약을 통해 학습 이용을 제한하기 위해 노력합니다. *(계약상 확정 문구는 §9-1 확인 필요)*
> - **데이터 주권**: 언제든 내 기록의 열람·삭제를 요청할 수 있습니다.
> - **직접 관리**: 서비스 운영진이 시스템을 직접 관리합니다.

이 각색이 필요한 이유와 근거는 §9-1(열린 이슈)에 정리했다 — 원문의 "구글/카카오 인증으로 비밀번호 미저장"은 현재 사실과 다르다(AUTH-01b SNS OAuth 미구현, Credentials 방식은 비밀번호를 해시로 저장함).

> ⚠️ **이 섹션은 웹뿐 아니라 앱에도 필요하다.** [`01-landing.md`](./01-landing.md) §8 "신규 개발 범위"에 앱 index 화면 또는 온보딩 축약 배치를 명시해 두었다.

### ⑥ 마무리

## 5. API 엔드포인트

이 화면은 웹 전용이므로 NestJS가 아닌 **기존 Next.js Route Handler** 컨벤션(`app/app/api/*`)을 따른다(§1 참고).

| Method | Path | 설명 | 상태 |
|---|---|---|---|
| GET | `/api/testimonials` | 게시된(published) 후기 목록 조회 (공개, 비로그인 가능) | 신규 — `/api/qna/published`와 동일 패턴 |
| POST | `/api/testimonials` | 후기 등록 (로그인 시 userId 자동 연결, 비로그인 시 방문자 이름 필수 입력) | 신규 — `/api/qna`(POST)와 유사하나 인증 필수가 아님 |
| GET | `/api/admin/testimonials` | 관리자 — 후기 목록(검수 대기 포함) 조회 | 신규 — `/api/admin/qna`(GET)와 동일 패턴 |
| PATCH | `/api/admin/testimonials/[id]` | 관리자 — 상태 변경(게시/숨김), 내용 수정 | 신규 — `/api/admin/qna/[id]`(PATCH)와 동일 패턴 |
| DELETE | `/api/admin/testimonials/[id]` | 관리자 — 후기 삭제 | 신규(기존 QnA 관리자 API에는 DELETE가 없음 — 후기는 완전 CRUD가 필요하므로 추가) |

가격·결제 관련 엔드포인트는 이번 범위에서 신규로 만들지 않는다. 기존 `POST /api/approvals/pay`(목업 결제)에 **티어(tier) 파라미터가 아직 없다** — §8 신규 개발 범위 참고.

## 6. 데이터 모델

### 신규: `testimonial` (후기)

`qna_question`(`app/lib/db/schema.ts` 522~548행) 테이블 스타일을 참고해 아래와 같은 컬럼 구성을 제안한다(중간 상세도 — 정확한 DDL은 구현 시 확정).

| 컬럼 | 설명 |
|---|---|
| `id` | PK, `crypto.randomUUID()` 기본값 (기존 테이블들과 동일 패턴) |
| `userId` | `users.id` FK, **nullable**, `onDelete: "set null"` — 로그인 사용자면 연결, 방문자면 `null` (여기가 `qna_question.userId`와의 핵심 차이점: QnA는 `notNull()` + `cascade`, 후기는 optional + `set null`) |
| `authorName` | 표시용 이름. 로그인 사용자는 `users.name` 스냅샷 또는 미입력 시 비워둘 수 있고, 방문자는 필수 입력 |
| `content` | 후기 본문 |
| `rating` | (선택) 별점 등 |
| `status` | `pending`(기본) → `published` / `hidden` — `qna_question.status`와 유사한 상태 관리 |
| `isMock` | 초기 목업 시드 데이터 구분용 boolean (실제 후기 유입 후 목업만 골라 정리하기 위함) |
| `publishedAt` | 게시 시각 |
| `createdAt` / `updatedAt` | 공통 타임스탬프 |

인덱스는 `qna_question_status_created_idx`(544행)와 동일하게 `(status, createdAt)` 조합을 권장.

## 8. 신규 개발 범위 요약

1. **랜딩 페이지 재구성**: `app/app/page.tsx`를 8개 섹션 순서로 재작성. 기존 히어로·기능소개·CTA·푸터는 카피/순서만 조정, 요금제·FAQ 섹션은 기존 주석 코드를 되살리되 내용 전면 교체.
2. **후기 기능 (신규)**:
   - 1단계: 목업 배열(기존 `plans`/`faqs`처럼 `page.tsx` 또는 `content/testimonials.ts`에 하드코딩)로 우선 출시.
   - 2단계: `testimonial` 테이블 신설(§6) + `/api/testimonials`(공개 GET/POST, FK 옵션) + `/api/admin/testimonials`(관리자 CRUD) + `/admin/testimonials` 관리 화면(AdminQnaClient 패턴 재사용) 구현.
3. **개인정보보호 후킹 섹션 (신규)**: 웹·앱 공통 축약 문구 확정 필요(§9-1 조정 후). 앱 쪽 반영은 [`01-landing.md`](./01-landing.md) §8 참고.
4. **가격·기능 매트릭스 (신규)**:
   - 랜딩에 정적 콘텐츠로 표시하는 것은 이번 범위(디자인+카피).
   - **티어별 사용량 제한(quota) 로직은 현재 전혀 없다** — 무료 사용자가 챕터2 이상 진입을 막거나, STT/TTS/AI 글쓰기/질문 생성 횟수를 재는 로직 자체가 코드에 없음. 실제 과금 강제(enforcement)는 별도 백로그로 분리 필요.
   - 결제(`approval_request` 또는 신규 `order` 테이블)에 티어·금액 컬럼 추가 필요.
   - T2(AI 영상)는 사용자 대상 생성 파이프라인이 아직 없으므로(관리자 전용 설계만 존재), 실제 판매 전에 파이프라인 완성이 선행되어야 한다.
5. **FAQ 요약 + 이동 버튼**: 기존 `/faq` 라우트로 연결하는 CTA만 추가하면 되므로 상대적으로 저비용.
6. **SNS 링크 (신규)**: 실제 계정 URL 확정 필요(§9-6).
7. **가격 정책 사업 문서 정합화**: `02-웹앱-분리-로드맵.md`의 T1/T2/T3 정의를 이번 신규 가격 체계로 갱신하거나, 두 문서 간 차이를 명시적으로 병기할지 결정 필요(§9-2).

## 9. 열린 이슈 / 가정

1. **[핵심] 개인정보보호 문구의 "구글/카카오 인증으로 비밀번호 미저장" 표현은 현재 사실과 다르다.** 현재 웹은 NextAuth **Credentials**(이메일+비밀번호) 방식만 구현되어 있고(`app/lib/auth.ts`), 비밀번호는 `bcrypt`로 **해시해 저장한다**(저장 자체는 한다 — "미저장"이 아니라 "평문 미저장·해시 저장"이 정확하다). SNS OAuth(AUTH-01b)는 아직 미구현이다. 두 가지 조정안 중 선택 필요:
   - (A) "SNS 로그인 도입 예정" 전제로 문구를 그대로 두고 실제 도입 시점에 맞춤 (로드맵상 SNS 로그인 일정 없음 — 확정 전까지는 노출 자제 권장)
   - (B, 이 문서가 §4-③에서 채택) 현재 구현에 맞게 "비밀번호는 암호화(해시)하여 저장, 본인 세션에서만 접근"으로 즉시 조정
   - 또한 "AI 학습에 무단 사용되지 않음"은 코드에서 OpenRouter 측 학습 옵트아웃 설정을 확인하지 못했다(`app/lib/openrouter.ts` 확인, 관련 플래그 없음) — **실제 계약/약관 확인 후 문구 확정 필요**. "개발자가 직접 관리"는 코드로 검증 가능한 사실이 아니라 운영 조직 사실이므로 그대로 두되 마케팅 팀 확인 필요.
2. **[핵심] 가격 체계가 기존 로드맵과 다르다 — 명시적 비교:**

   | 항목 | 기존(`02-웹앱-분리-로드맵.md`, `03-사업-운영-마케팅.md`) | 이번 신규 스펙 |
   |---|---|---|
   | T1 | 전자책만 | 전자책 **+ 오디오북** |
   | T2 | 전자책 + 오디오북 | T1 **+ AI 영상 자서전** |
   | T3 | T2 + 인쇄북(POD, 2~4권 가정) | T1 **+ 인쇄책**(AI 영상 제외, 4권부터) |
   | T4 | (존재하지 않음) | all(T1+T2+T3) — **신규 티어** |
   | 금액 | 미정(가격 수치 없음) | **이번에 처음 구체적 원화 금액 확정**(39,000~129,000원+) |
   | "무료" 개념 | 사전신청 100명 한정 **T2(전자책+오디오북) 전체 무료** 프로모션(~10월, 부스·추석 마케팅용) | **상시** 무료 티어 = 챕터1까지만(전체 무료가 아님) |

   즉 이번 스펙은 기존 로드맵의 티어 구성·명칭을 재정의했고, 별도로 존재하던 "사전신청 100명 무료 T2" 프로모션과 "상시 무료(챕터1까지)" 티어가 **서로 다른 메커니즘으로 공존**하게 된다. 부스·마케팅 문서(`docs/2026-08-21-부스-스크립트-및-SNS-구조.md`)의 "무료 T2" 안내 문구와 이번 랜딩의 "무료(챕터1까지)" 문구가 같은 화면에 동시에 노출될 경우 사용자 혼란 가능성 — **사업 측 확인 후 두 메시지의 관계(프로모션이 상시 무료 티어를 대체/추가하는지)를 명확히 정리 필요.**
3. **무료 티어의 정확한 범위가 스펙 원문 내에서도 두 가지로 읽힌다.** 사용자 스펙은 "챕터1의 1장까지 무료(목차 생성 → 1장 작성 → 리뷰까지)"라고 설명했지만, 매트릭스 서술 지침에는 "무료: 1차 답변까지만"이라는 표현도 있다. 두 해석이 다르다:
   - **해석 A(이 문서 채택)**: 챕터 단위 — 목차 전체 확인 + 챕터1(첫 번째 장) 전체 질문의 1차답변→꼬리질문→확정 저장까지 완료 + 챕터1 노트북 리뷰까지 무료. 챕터2부터 잠금.
   - **해석 B**: 단계 단위 — 모든 챕터의 질문에 대해 "1차 답변" 제출까지만 무료이고, AI 꼬리질문·윤문(확정 저장)은 유료.
   해석 A가 "챕터1의 1장까지"라는 챕터 지칭과 더 직접적으로 일치한다고 판단해 채택했으나, **최종 확정은 사업 측 결정 필요.**
4. T3(=T1+인쇄책)의 사진 업로드 한도가 명시되지 않았다. 매트릭스에는 "T1은 기본 10장, T2부터 무제한"이라고만 명시되어 있고, T3는 T2를 거치지 않는 조합(T1+인쇄)이라 문자 그대로 해석하면 T1과 동일하게 10장으로 보인다. 매트릭스에 그렇게 반영했으나(§4-④), T3 구매자가 인쇄책에 넣을 사진이 부족할 수 있다는 점에서 사업적으로 재검토가 필요할 수 있다.
5. FAQ 요약 섹션에 표시할 콘텐츠 소스를 `app/app/page.tsx`의 기존(주석 처리된) `faqs` 배열로 할지, 실제 `/faq` 페이지가 쓰는 `app/content/faq.ts`에서 대표 항목만 뽑아 쓸지 결정 필요 — 후자가 콘텐츠 이원화를 막아 유지보수에 유리해 보이나 확정은 구현 시점 판단.
6. SNS 링크(인스타그램/블로그/유튜브 등)의 실제 계정 URL이 아직 없다 — 현재 코드베이스에 SNS 링크가 전혀 존재하지 않는다(회원가입 폼의 SNS 로그인 관련 언급 제외). 마케팅 측에서 계정 확정 필요.
7. 가격 정책을 정적 페이지 콘텐츠로만 둘지, `app_setting`처럼 관리자가 값을 바꿀 수 있는 설정으로 둘지는 이번 "화면 개발가이드"의 범위를 넘는 결정이라 이번 문서에서는 정적 콘텐츠로 가정했다. 가격이 자주 바뀔 예정이라면 별도 설계 필요.
