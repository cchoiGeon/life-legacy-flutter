## 1. 접근

기존 `feature/<화면>/{binding,controller,view}` 구조와 `ApiClient` 추상 계약을
**그대로 두고** 화면별로 시안에 맞게 고친다. 새 화면 트리를 따로 파지 않는다 —
컨트롤러·모델이 이중화되고 죽은 코드가 남는다.

색 토큰(웜브라운·크림)은 이미 시안과 같다. 바뀌는 것은 **배치 · 문구 · 흐름**,
그리고 아래 §2의 **치수·타이포 토큰 몇 개**다.

## 4. 화면별 변경

### A · 온보딩 · 로그인

- **A1 스플래시** — 크림 배경. 책 마크 84 + `Life Legacy`(명조) + `말로 이야기하면 자서전이 됩니다`.
- **A2 로그인** — 상단 브랜드, 하단 카카오(노랑) + 전화번호(아웃라인) 62px 2개 + 약관 문구 한 줄.
- **A3·A4 전화번호** — 제목 `전화번호를 알려주세요` / 부제 `인증 문자를 보내드려요` /
  필드 `010 - 0000 - 0000` / CTA `인증번호 받기` / **하단 고정 숫자 키패드**.
- **A5·A6 인증번호** — 제목 `인증번호를 입력해주세요` / 부제 `{전화번호} 로 보냈어요` /
  **6칸 박스** / `2분 47초 남음` ↔ `다시 받기`(brand Bold 15) / CTA `확인` / 키패드.
  에러 시 박스 위에 `인증번호가 맞지 않아요. 다시 입력해주세요.`

> **OS 키보드를 쓰지 않는다.** 시안이 앱 자체 키패드를 그렸다. `readOnly: true` +
> `showCursor: true` 로 필드를 두고 키패드가 `TextEditingController` 를 직접 만진다.

## 5. 데이터 · API 변경

```
IntroQuestion   + subtitle          B 부제
Chapter         + nextQuestionText  E1 "다음 질문 · 첫 소풍의 기억"
BookPage        + totalPages        E2 "12 / 34쪽"
Address         신규                받는분·연락처·우편번호·기본주소·상세주소
IntroProfile    신규                성별·결혼·자녀·학력 (F3)

ApiClient  + shippingAddress()            F3·F4
           + updateShippingAddress(Address)
           + introProfile()               F3
```

- `verifyCode` 는 그대로. **재발송 만료 3분**은 클라이언트 타이머(`LoginController`)로
  센다 — 서버 계약이 없어 만료 시각을 받을 수 없다. 실제 API가 붙으면 `expiresAt` 를
  받아 이 타이머를 갈아 끼운다.
- 목업 장 제목을 시안에 맞춘다: `안동에서의 어린 시절` → **`어린 시절`**,
  `지금의 나, 남기고 싶은 말` → **`지금의 나`**.
- 목업 알림 7건을 시안 문구로 교체.
- `MockApiClient` 에 **저장 실패 1회 주입** 스위치를 둔다 (D5 를 눈으로 볼 수 있어야 한다).

## 7. 뒤집는 기존 결정

README 에 근거와 함께 적혀 있던 것 중 시안이 **반대로** 그린 것들. 시안을 따르고
README 도 같이 고친다.

| 지금 | 새 시안 | 왜 뒤집히나 |
|---|---|---|
| 고르기 문항은 누르는 즉시 다음 | 고르고 → 하단 `다음` | 4지선다가 생겨 오답 정정 여지가 필요하다 |
| 선택지는 항상 같은 모양 | 고른 쪽이 크림으로 채워진다 | 선택 후 `다음`을 누르려면 무엇을 골랐는지 보여야 한다 |
| 선택지 2개 가로 배치 | N개 세로 배치 (96 / 74) | B5 가 4지선다다 |
| 5번 `대학교까지 다니셨나요? 예/아니요` | `학교는 어디까지 다니셨나요?` 4지선다 | — |
| 전화·인증은 OS 키보드 | 앱 자체 숫자 키패드 | 시니어 대상 — 키 크기·배치를 앱이 통제한다 |
| 책 미리보기 장 단위 | 쪽 단위 (`12 / 34쪽`) | — |
| 홈에 인사말 | 인사말 제거 + 목차 인라인 | "요소 최소화" 원칙 |
| 자기소개 5칸 분절바 없음 · 진행바 6px | 전체폭 4px | — |
